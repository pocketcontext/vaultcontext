ONE FILE, WITH ITS FULL CONTEXT

Example source path → encrypted file name

/home/ubuntu/code/pocketcontext/.envrc

Pass this absolute path to save and it becomes the default display name. Relative paths stay relative; --name lets you choose another label.

The path is a label, not a restore instruction. You always choose the destination. Saving changes is explicit: use --document DOCUMENT_ID to add a version to an existing file. There is no automatic sync.

THE ONBOARDING MANUAL

Your first .env,
safely stored.

A guided path from installation to saving and restoring a harmless example .env file.

Before you begin

You need Linux or macOS, a terminal, internet access for installation, and an eligible Google Workspace account for your VaultContext instance.

This page is a guide. Run the commands on the machine where you want to manage your files.

Full workflow reference ↗
01Choose your way inInstall the client or the agent skill+

Install Node.js/npm (for npx) and uv, then run these commands from your workspace. The skill includes the standalone vc launcher; copy it onto your PATH.

npx skills add pocketcontext/vaultcontext --skill vaultcontext --agent codex claude-code --yes
mkdir -p ~/.local/bin
cp .agents/skills/vaultcontext/vc ~/.local/bin/vc
chmod 755 ~/.local/bin/vc
export PATH="$HOME/.local/bin:$PATH"
vc --help

Keep uv on PATH. It supplies Python and downloads the pinned client and dependencies on first use. Add the PATH export to your shell configuration for future terminals. To update, reinstall the skill and copy the launcher again; lock and unlock any existing session afterward.

With Node.js/npm and uv installed, run these commands from your workspace to install the skill for Codex and Claude Code and copy its CLI launcher onto PATH.

npx skills add pocketcontext/vaultcontext --skill vaultcontext --agent codex claude-code --yes
mkdir -p ~/.local/bin
cp .agents/skills/vaultcontext/vc ~/.local/bin/vc
chmod 755 ~/.local/bin/vc
export PATH="$HOME/.local/bin:$PATH"
vc --help

The skill’s portable launcher requires uv. Ask your agent to read the installed skill, then complete the steps below in your terminal. Keep uv and ~/.local/bin on PATH; uv manages Python and the client dependencies.

“Use the VaultContext skill to help me set up the client. I’ll enter my passphrase privately in my terminal.”

Agents manage files and metadata through the skill; they can check equality with compare without seeing file contents or hashes. They must not inspect file contents. Your unlocked machine and agent are trusted.

02Connect your accountSign in to your Workspace instance+

Replace the email with your eligible Workspace identity. If your team hosts its own instance, replace the URL too.

export VAULTCONTEXT_URL=https://vault.pocketcontext.com
export VAULTCONTEXT_USER_EMAIL=you@pocketcontext.com
vc login --google
vc whoami
vc check

Google sign-in identifies you. It does not decrypt or unlock your files. Public signup is blocked; contact your instance operator if you need access.

Working over SSH? Forward callback port 8765 with ssh -L 8765:127.0.0.1:8765 user@host and open the login URL on your browser computer. Decryption still happens on the remote host.

03Make it yoursCreate your encryption identity and first vault+
Your passphrase matters.

There is no recovery key. Losing your passphrase without a usable unlocked session or an enrolled macOS Keychain credential means losing access. Google account recovery cannot decrypt your vault.

For a new account, run vc init once. Enter your passphrase only at the private terminal prompt—never in chat, command arguments or environment variables. If already initialized, skip init.

vc init
vc unlock --timeout 900
vc create 'Confidential dotfiles'

Keep the vault ID returned by create for the next step. You can find it again with vc vaults. Keys stay in the client’s memory while unlocked; the session expires after 15 minutes with this setting.

Optional: unlock with macOS Keychain

First install the separately signed native helper using the macOS Keychain setup guide. Then enroll in your private terminal with your existing vault passphrase:

vc keychain-enroll
vc unlock --keychain

Keychain stores the passphrase on this Mac. Retrieval requires Touch ID or macOS credential authentication; macOS may still ask for a password. Ordinary vc unlock keeps the terminal prompt. The unlocked session trusts your same-user agents as before.

lock and logout keep enrollment. Use vc keychain-forget while logged in to remove it, and vc lock separately to end an active session. After changing your vault passphrase, enroll again with the new passphrase.

04Save. Compare. Restore. Lock.Try the full round trip with a sample .env+

Create a synthetic .env in a fresh temporary directory. These example values contain no secrets. Keep the same terminal open for these commands.

vault_demo_dir=$(mktemp -d)
vault_demo_dir=$(cd "$vault_demo_dir" && pwd -P)
printf 'APP_ENV=demo\nAPI_TOKEN=example-not-a-secret\n' > "$vault_demo_dir/.env"

Replace VAULT_ID with the ID returned in step 3, then save:

vc save VAULT_ID "$vault_demo_dir/.env"

Without a --name override, the encrypted name preserves the source path, such as /tmp/tmp.EXAMPLE/.env. For your own files, pass an absolute path to retain the full location.

Replace DOCUMENT_ID with the document ID returned by save (or find it with vc list VAULT_ID). Compare the saved version with your local file, restore to a new path, and close your unlocked session:

vc history DOCUMENT_ID
vc compare DOCUMENT_ID "$vault_demo_dir/.env"
vc restore DOCUMENT_ID --to "$vault_demo_dir/.env.restored"
vc lock

Your first round trip is complete when comparison reports "same": true and restore reports success. You’ve saved an encrypted .env, restored it to a separate path, and locked your session.

Comparison returns equality without displaying contents or hashes. New saves keep their checksum inside encrypted, signed metadata, so comparison needs no stored file download. Older versions are downloaded and verified in memory. The client still reads your local bytes internally; equality alone does not prove stored files are recoverable.

After upgrading the client, run vc lock and vc unlock again before using new commands.

Restores preserve exact bytes and use private file permissions. Existing files are protected from overwrite by default. The sample remains in your vault and temporary directory. VaultContext never sources or activates files. Restoring an .envrc into a direnv-enabled directory can cause your shell to execute it later; choose the destination deliberately.

GOOD TO KNOW

Privacy, with clear boundaries.

What does the server know?+

File contents, names and descriptive metadata are encrypted. The server still handles account identities, memberships and operational metadata. Application authority does not grant an operator your decryption keys.

What happens when I share a vault?+

Sharing grants access to the entire vault and all retained history. Verify fingerprints through a separate trusted channel first. Use a dedicated vault when sharing just one file. Revocation cannot recall files or keys someone already downloaded.

Is my unlocked agent trusted?+

Yes. The execution host and same-user unlocked agent are trusted. The skill tells agents not to inspect contents, but this is a behavior rule, not cryptographic isolation. Memory erasure cannot be guaranteed by the client runtime.

Where do I go next?+

Read the workflow manual for versions, sharing, fingerprint verification, revocation and encrypted exports, or the trust model for the security boundaries. Company-specific onboarding belongs in your team’s WikiContext.
